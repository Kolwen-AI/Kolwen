Kolwen has not launched. This page describes what kolwen.com does today, and says plainly which parts change on the day the assistant itself ships.

What this site is

หน้าคงที่ให้บริการโดย Cloudflare Worker Worker ทำงานด้วยสคริปต์ขนาดเล็กของเราหนึ่งไฟล์ (worker/index.mjs) สำหรับทุกคำขอไปยังพาธที่ไม่มีไฟล์คงที่ Worker ส่งคำขอนั้นไปยังหน้าเว็บ ดังนั้นพาธที่ไม่มีหน้าจะได้หน้า 404 ยกเว้นที่ Worker ตอบเองที่ /status.json และ /subscribe และทุก 15 นาที Worker ขอที่อยู่ของเราสิบสี่รายการ คือเจ็ดหน้าภาษาอังกฤษและเจ็ดหน้าชุดเดียวกันในภาษาไทย เพื่อตรวจว่าตอบสนองหรือไม่ Worker ไม่บันทึก ไม่เก็บ และไม่จัดเก็บคำขอของผู้เข้าชม ไม่มีฐานข้อมูล และไม่มีการจัดเก็บข้อมูลของผู้เข้าชมฝั่งเรา บันทึกสถานะเก็บเพียงเวลา ผลการตรวจของแต่ละหน้า และผลที่เจ้าของได้รับแจ้งครั้งล่าสุด ระบบเก็บผู้สมัครรับข่าวสารถูกสร้างไว้แต่ปิดอยู่ ขณะที่ปิด ไม่มีที่อยู่ใดถูกเก็บ และไม่มีอีเมลส่งถึงผู้สมัครในการสร้างนี้ เมื่อตั้งที่อยู่สำหรับการแจ้งเตือนแล้ว Worker พยายามส่งอีเมลถึงเจ้าของเมื่อผลการตรวจเปลี่ยน คือจากทุกรายการผ่านเป็นมีรายการล้มเหลว โดยระบุพาธ สถานะ HTTP หรือข้อผิดพลาดของแต่ละรายการที่ล้มเหลว (เวลาหมดหรือข้อผิดพลาดของเครือข่าย) เวลาที่ใช้ ผลประเภทเนื้อหา จำนวนรายการที่ล้มเหลว และเวลา UTC และจากล้มเหลวกลับเป็นทุกรายการผ่าน พร้อมหมายเหตุการกู้คืน เมื่อบันทึกสถานะถูกผูกไว้และอ่านได้ ความล้มเหลวที่ยังคงอยู่จะไม่ถูกส่งอีเมลซ้ำหลังเจ้าของได้รับแจ้งแล้ว และการส่งที่ล้มเหลวจะถูกลองใหม่ในรอบถัดไปที่ยังพบความล้มเหลวนั้น (ระหว่างนั้น และทุกครั้งที่อ่านบันทึกไม่ได้ ทุกการตรวจที่ล้มเหลวจะถูกส่งอีเมล) อีเมลทั้งสองแบบไม่มีข้อมูลของผู้เข้าชม (การส่งที่ล้มเหลวถูกบันทึกโดยประเภทข้อผิดพลาดเท่านั้น) จนกว่าจะตั้งที่อยู่ ไม่มีอีเมลใดถูกส่ง

Measured: grep -nE '^[[:space:]]*"main"' wrangler.jsonc returns one line, "main": "worker/index.mjs",; the config declares a name, a compatibility date, the assets block, a cron trigger (*/15 * * * *), the observability block with invocation logs off and Workers Issues on, the send_email binding, one variable (ALERT_FROM) and an empty previews block. The alert recipient is a secret set outside the file, so the file holds no recipient address; its one address is the sender, the published info@kolwen.com in ALERT_FROM.

If either is ever switched on for this site, the sentence above, "no cookies at all", would be reworded the same day. Both are off today.

วัดผลเมื่อ 2026-11-18: ใน web/ การเรียกใช้ที่เก็บข้อมูลมีเพียงจุดเดียวคือ localStorage.removeItem('kolwen-lang') ซึ่งแต่ละหน้าทั้ง 22 หน้ารันภายใน try ที่ไม่สนใจความล้มเหลว ไม่มีส่วนใดเรียก setItem หรือ getItem และไม่มีหน้าใดตั้งคุกกี้ โค้ดใน web/ ไม่ใช้ sessionStorage, indexedDB หรือ document.cookie

Worker logs. Today the Worker logs the result of each of its own page checks (the path, status, timing and error class) and, when the result of the checks changes, one line saying whether an alert was sent, not sent because no alert address is set, or failed (with the error's class only), and one line when the status record cannot be saved (again the error's class only); never a visitor's request (see "What this site is"). Invocation logs are switched off in wrangler.jsonc. When the Worker first answers visitors' requests with code of ours (an API, a payment-provider webhook or a chat endpoint) with invocation logs switched on, Cloudflare Workers Logs will record each such request. Switching it on is Cloudflare's setting, and the page says "All newly created Workers will come with the observability setting enabled by default". Cloudflare's documentation (https://developers.cloudflare.com/workers/observability/logs/workers-logs/, page last updated Oct 12, 2026, read 2026-10-17) says an invocation log contains details such as the request, the response and related metadata, that a fetch request's message shows the request method and the request URL, and that anything the Worker prints with console.log is stored too. The same page gives a retention of 3 days on the Workers plan without a monthly charge and 7 days on the paid Workers plan, in its table "until then" (until 30 November 2026), and says "Beginning December 1, 2026, Workers Logs will use Cloudflare Observability pricing". For the period after that date it names no retention for either plan; its limits table gives only a "Maximum log retention period" of 7 days.

Who else sees your request

Cloudflare serves this site, so it necessarily handles your request: your IP address, the URL you asked for, and your browser's user-agent reach their edge before any bytes reach you. That is how any hosted site works, and it is not something we can turn off while remaining online. Cloudflare no longer injects its bot-detection script into the served HTML: the zone's JavaScript Detections setting was switched off on 2026-10-07, and Bot Fight Mode is off.

Two parties outside those systems do handle data, as this notice already says: Cloudflare handles every request; and the mailbox behind the contact address holds what you send to it. What each retains cannot be measured from this repository.
